# Защита Career Quest: 3–5 минут

## До демонстрации

1. Настроить `.env`: `AI_PROVIDER=openai`, свой `OPENAI_API_KEY`,
   `OPENAI_MODEL=gpt-4.1-mini`, `CQ_ALLOW_CLOUD_DATA=false`.
2. Запустить `python run.py --demo-ai --open-browser` или дважды щёлкнуть
   `start-ai-demo.cmd` на Windows. Откроется http://127.0.0.1:8001.
3. Войти как `E0001` / `quest-demo`. Убедиться, что интерфейс показывает режим
   независимых демоданных, провайдера и успешный ответ LLM. Если отображается
   fallback, устранить показанную причину; не представлять такой ответ как работу модели.
4. Если демонстрация уже проводилась, раскрыть «Повторить демосценарий» и нажать
   «Сбросить демопрофиль E0001». Это восстановит стартовые 50% только у этого
   сотрудника в отдельной демонстрационной базе.

AI-деморежим хранит собственные примеры и прогресс в `runtime/ai-demo/`.
Он не читает и не изменяет основной датасет и `runtime/career.sqlite3`.
Основное приложение при необходимости запускается отдельно: `python run.py`,
http://127.0.0.1:8000. Ключи, обе базы и датасет не входят в Git.

## Сценарий

1. **Проблема.** «Сотрудник получает список курсов, но не понимает, как они связаны с его карьерой».
2. **Цель.** Показать текущую роль Backend Engineer / Middle, цель Senior,
   общий прогресс **50%** и отдельную готовность критических навыков.
3. **Рекомендация.** Раскрыть «Почему этот шаг подходит». Показать фактический разрыв,
   требования цели, соответствие роли/грейду и историю участия. Объяснить, почему выбор
   не сводится к самому низкому навыку: Public Speaking равен 0, но критический
   System Design равен 2 при требовании 4. Показать статус реального ответа
   OpenAI; повторный подбор может использовать явно отмеченный кэш.
4. **Результат.** Отметить «Практику проектирования систем» выполненной.
   System Design становится **4**, прогресс — **70%**. Показать обновлённые
   рекомендации и запись в истории. Обновить страницу: результат сохранён.
5. **HR.** Выйти и войти в режиме HR. Показать дефициты компетенций и фильтры
   «Нет следующего шага» и «Нет завершений 90 дней». Это поддержка развития, не рейтинг.
6. **Проверка жюри.** Загрузить JSON и CSV через «Загрузка данных» или вставить
   их содержимое текстом, найти новый ID в HR-обзоре и открыть профиль. Для
   встроенного каталога подойдёт команда создания `JURY_DEMO` из README.
   Подбор пересчитывается на сервере. Импортированные профили и профили,
   затронутые импортом истории, при `CQ_ALLOW_CLOUD_DATA=false` используют
   подбор по правилам; автоматическое разрешение облачных запросов для них снимается.

Автоматическая проверка того же сценария на временных независимых примерах:

```bash
python scripts/check_ai_workflow.py
```

Скрипт проверяет настоящий ответ модели через HTTP API, завершение курса,
сохранение 70% и сброс к 50%. Он не меняет данные основного приложения или демосервера.

## На технические вопросы

- **Зачем LLM?** Выбирает среди допустимых кандидатов, сопоставляя контекст и несколько
  факторов. Ограничения и числовые объяснения проверяет детерминированный код.
  Навигатор встроен в блок следующего шага; отдельного чата и автономных действий нет.
- **Что при галлюцинации или тайм-ауте?** Невалидный ответ отбрасывается, показывается
  явно подписанный многофакторный fallback. У модели нет права менять данные.
- **Как избежать двойного роста?** Навыки профиля считаются оценёнными на
  `last_review_date`; применяются только более поздние завершения.
- **Где приватность?** Серверное разграничение прав, отдельные пароли сотрудников,
  ключ только на сервере, обезличенный запрос модели без имён и исходной истории.
  Датасет и локальные базы не публикуются в Git. При выключенном общем разрешении
  облако доступно только для собственных встроенных примеров отдельного AI-деморежима.
  Импорт снимает это разрешение для затронутых профилей, в том числе после перезапуска.
- **Что дальше?** Интеграция с LMS и SSO, проверка качества на профилях жюри,
  подбор формата после повторных пропусков и оценка эффекта на завершаемость.

## Работа с Git для команды

Работа ведётся в репозитории платформы:
https://github.com/BAITC-Hacks/hack-176032e6-ggbyte

Перед новой работой при чистой папке:

```bash
git pull --ff-only
```

После проверенного законченного изменения:

```bash
git status
git add <конкретные-файлы>
git commit -m "Краткое описание реального изменения"
git push
```

Коммиты отражают реальные этапы разработки. Не переписывайте общую историю и не
используйте `git push --force`. `.env`, `data/` и `runtime/` игнорируются Git.
