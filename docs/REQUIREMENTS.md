Геймификация явно исключена из обязательной части ТЗ. Публичных рейтингов,
баллов за обязательные процессы и реальных персональных данных в решении нет.
ТЗ требует AI-слой, но не предписывает несколько агентов, отдельный агентный
фреймворк или автономное выполнение действий за сотрудника. Здесь LLM выбирает
шаги, а код проверяет доступность и рассчитывает последствия. Это описание
фактической реализации, а не заявление о наличии мультиагентной системы.

## Модель и граница данных

Общие сведения ТЗ разрешают облачные и локальные модели. OpenAI API поэтому
допустим как технология. Одновременно раздел о данных ограничивает вынос
выданного датасета за пределы хакатона. Прямого разъяснения о передаче производных
обезличенных признаков внешнему провайдеру в документе нет.

Поэтому подключение API описано как настройка развёртывания. Ключ не публикуется,
данные организаторов не коммитятся. `CQ_ALLOW_CLOUD_DATA` управляет передачей
признаков; локальная Ollama этой передачи не требует. Без разрешённого облачного
режима или работающей локальной модели полный AI-сценарий ещё не подтверждён.
Режим правил — отказоустойчивость, а не замена AI при приёмке.

OpenAI проверен живым запросом на независимом примере из `examples/demo.py`:
критический System Design выбран первым, задержка 4,15 с. Это не оценка качества
на скрытых профилях жюри. NVIDIA и Ollama требуют отдельной живой проверки.

## Репозиторий и правила мероприятия

Разработка ведётся в [репозитории команды, созданном платформой](https://github.com/BAITC-Hacks/hack-176032e6-ggbyte).
История сохраняет исходный коммит платформы; текущая ветка `main` отслеживает
`origin/main`. Сайт HackAlem прямо требует использования Codex при разработке.

Пользователь также предоставил правило работы только в репозитории платформы.
В [публикации AI Qazaqstan от 18 сентября](https://aiqazaqstan.com/ru/articles/правила-hackalem-ai-что-нужно-знать-участнику)
со ссылкой на Telegram HackAlem говорится о почасовой фиксации прогресса и риске
дисквалификации. Указанный первоисточник `https://t.me/hackalem/1673` при проверке
недоступен (Telegram возвращает «Channel not found»), поэтому публикация не
выдаётся за проверенный полный регламент. Точный механизм фиксации и минимальное
число коммитов по доступным первичным источникам установить не удалось.

Практика команды: отправлять реальные законченные изменения по ходу работы,
сохранять настоящую историю, не откладывать весь проект до финальной загрузки.
Историю задним числом и фиктивные коммиты не создавать. Гарантию допуска может
дать только организатор; техническая привязка Git не подтверждает регистрацию
команды или офлайн-присутствие.

## Что означает готовность

Проверки текущей версии: 18 автоматических тестов пройдены; локальная диагностика
обработала 200 профилей, 40 событий, 60 навыков и 2744 записи сохранённой истории.
Расчёт для всех профилей занял 0,086 с (это не замер браузера или LLM).
В отдельной чистой копии без `.env`, SQLite и выданного датасета команда
`python run.py` создала независимые примеры: вход, HTML, завершение активности
с изменением прогресса 50% → 70% и HR-запрос прошли; HR ответил за 0,017 с.
Эти результаты относятся к ноутбуку команды, не заменяют проверку среды жюри.

Для хакатона проверяется полный основной сценарий: профиль → рекомендация LLM →
объяснение → завершение → сохранённый прогресс → HR и импорт. API-ключ или
установленная локальная модель — явная предпосылка запуска, описанная в README.
Установить ключ, но оставить AI выключенным, недостаточно для демонстрации этого
сценария. Для внедрения в банк потребуются SSO, интеграция LMS, инфраструктура
и эксплуатационные проверки; текущая версия предназначена для локальной приёмки.
