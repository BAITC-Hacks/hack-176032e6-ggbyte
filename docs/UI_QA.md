# Проверка интерфейса Career Quest

Дата: 23 сентября 2026 года. После расширения интерфейса и демоданных пройдены **60 из 60 тестов**, проверены новые каталоги в браузере и **30 сочетаний раздела и ширины окна** без горизонтального переполнения страницы.

## Что изменилось

| Раздел | Проверяемые возможности |
| --- | --- |
| Обзор сотрудника | Цель и прогресс, явный статус AI, рекомендации, фокус развития и последние активности |
| Сравнение рекомендаций | Длительность, формат, изменения навыков и прогноз каждого из 2–3 шагов отдельно |
| Цель и навыки | Поиск по названию, фильтры всех, требующих развития, ключевых и достигших цели навыков |
| Карьерные траектории | Требования и рассчитанная готовность к каждой роли/грейду; фильтры и выбор одной активной цели |
| Обучение | Каталог с описаниями, эффектами и условиями; поиск, навык, доступность и отметка о завершении |
| История | Поиск, статус, период 30/90/365 дней, порядок по дате, сброс и счётчик результатов |
| HR | Три группы карьерных маршрутов; метрики фильтруют сотрудников; поиск, роль, состояние и сортировка |
| Аналитика HR | Все возвращённые сервером разрывы навыков — до 12; поиск и фильтры активностей по участию |
| Импорт | Прежние формы JSON/CSV и вставки текста; профиль доступен в обновлённом HR-списке |

Пустые выборки показывают причину и способ изменить фильтры. Отсутствие доступного шага и достижение цели имеют разные сообщения. Фильтры работают в браузере и не изменяют данные.

Периоды истории рассчитаны относительно даты среза данных, а не даты компьютера. В сравнении рекомендаций проценты не суммируются: каждый прогноз рассчитан от одного текущего состояния.

## Адаптивность

Проверена матрица **«Обзор», «Цель и навыки», «Обучение», «История», «Сотрудники», «Импорт» × 360, 390, 768, 1024 и 1440 px**. Во всех **30 из 30** проверок `scrollWidth <= clientWidth`, фактическая ширина окна соответствовала заданной. В консоли браузера ошибок не обнаружено. Широкие таблицы сохраняют собственную прокрутку.

Итоговый обзор на 1440 px сопоставлен с предыдущим видом. Визуально проверены карьерные цели на 1440 и 768 px, каталог обучения на 1440 и 390 px. При переходе клавишей Tab от фильтра доступности к кнопке «Сбросить» виден сплошной контур фокуса. Эти измерения и просмотры подтверждают перечисленные состояния в проверенном браузере, но не заменяют полный аудит доступности.

## Данные и сохранение прогресса

По исходному `examples/demo.py` чистый набор содержит **8 сотрудников, 12 навыков, 22 активности и 26 записей истории**. Для трёх ролей — Backend Engineer, Data Analyst и QA Engineer — заданы четыре грейда: всего **12 вариантов цели**. Основная траектория `E0001` сохраняется: 50% → 70% → 80% → 90% → 100%.

Сервер возвращает рассчитанные варианты цели в `goal_options`, а каталог активностей — в `catalog`. Интерфейс `goals.js` фильтрует цели и сохраняет выбор через прежний API цели. `catalog.js` показывает описания, изменения навыков и причины недоступности; завершение использует прежний API с серверной проверкой доступности. Учебный курс внутри приложения не запускается.

Добавляющее обновление собственной демонстрационной базы сохраняет существующие цели, навыки, завершения и импортированные профили. В собственные встроенные профили добавляются отсутствующие навыки; новые профили и их история дополняют набор. История `E0001` не восстанавливается и не дублируется. База без сохранённых сведений о происхождении не получает автоматическое обновление доверенных данных.

При проверке цепочек курсов исправлен порядок завершений в один день: сортировка по случайному ID могла переставить базовый и продвинутый курс с разными пределами роста. Теперь сервер сохраняет последовательность интерактивных завершений, и пересчёт после сохранения применяет их в фактическом порядке. Сортировка исходных записей без этой последовательности сохраняет прежнее поведение.

## Функциональная проверка

| Проверка | Результат |
| --- | --- |
| Полный набор Python-тестов | **60 из 60 пройдены** |
| Цепочка завершений в один день через HTTP | При намеренно обратных ID уровень ANALYSIS растёт 1 → 3 → 5; цель Data Analyst / Lead достигает 100%, результат сохраняется после повторного открытия SQLite |
| Цепочка через браузер после перезапуска с исправлением | Для Data Analyst / Lead базовый курс поднимает ANALYSIS 1 → 3 и прогресс 22% → 30%; открывшийся продвинутый — 3 → 5 и 30% → 37%; после обновления страницы уровень 5 сохранён, ошибок консоли нет |
| `node --check` | Все пять файлов: `app.js`, `workspace.js`, `hr.js`, `goals.js`, `catalog.js` — без синтаксических ошибок |
| HR на новом наборе | Восемь сотрудников, 12 навыков в сводке разрывов, 22 активности |
| Фильтр HR по роли Data Analyst | Два сотрудника из восьми |
| Выбор карточки Data Analyst / Senior для исходного `E0001` | Цель сохранена, готовность — 25% |
| Настоящий запрос OpenAI после смены цели | `gpt-4.1-mini`, ответ примерно за 2,0 секунды |
| Каталог: SQL + «Доступны сейчас» | Одна активность из 22 |
| Завершение SQL из каталога | Прогресс 25% → 35%; в завершённой карточке текущий SQL равен 3, повторная кнопка отключена |
| Сброс фильтров карьерных траекторий | Показаны все 12 из 12 целей |
| Сохранённая демобаза после добавления содержимого | Карта расширена до 12 навыков; прежняя цель Middle, прогресс 100% и четыре завершения сохранены |
| Основное приложение с датасетом организаторов, только чтение | HR показывает 200 из 200 сотрудников, каталог — 40 из 40 активностей; 32 карьерные цели, из них восемь на выбранном грейде |
| История и списки | Проверены фильтры статуса/периода, пустая выборка и восстановление списка сбросом фильтров |
| Импорт через интерфейс | Независимый профиль добавлен и найден в HR; пустая отправка показывает ошибку без изменения данных |

Сценарии смены цели, завершения и импорта проверялись на временном QA-наборе на порту 8002. Сохранённая демобаза пользователя на порту 8001 обогащена без сброса прогресса. В основном приложении на порту 8000 проведена браузерная проверка только чтением: цели не менялись, активности не завершались.

## Границы проверки

- Проверены отдельные сочетания цветов текста и фона. Полный аудит соответствия WCAG и проверка всех состояний со скринридером не проводились.
- Изменение данных проверялось в локальном браузере на независимых примерах; основной датасет просматривался только чтением. Результаты не являются проверкой всех браузеров, устройств, профилей жюри или нагрузки.
- Успешный ответ OpenAI подтверждает конкретный запуск. Доступность API и время будущих ответов зависят от провайдера и сети; fallback остаётся явно обозначенным.
- Облачная обработка официального датасета на порту 8000 остаётся отключённой. AI-деморежим на порту 8001 использует собственные примеры и прежнюю защиту импортированных профилей.
- Чат-бот, автономные действия и интеграции LMS или SSO не добавлялись.
